Many problems contain fine-scale dynamics that would require meshes beyond what is commonly computationally affordable. Therefore, one evolves a filtered field uˉ rather than the full ut​=N(u). Filtering both sides gives ∂t​u​=N(u)​, and if the filter does not depend on time, ∂t​u​=∂t​uˉ, so ∂t​uˉ=N(u)​. This equation is exact but not closed, since it requires the fine field u, while a coarse solver only stores uˉ and can compute only N(uˉ). One can, however, rewrite

N(u)​=N(uˉ)+(N(u)​−N(uˉ))=N(uˉ)+τ

so that τ=N(u)​−N(uˉ) is the commutation error between the filter and the nonlinear N — it is what must be added to the coarse side to make it exact. Dropping τ leaves an equation that is cheap to step but wrong. Instead, one learns τ from filtered high-resolution data so that the coarse solver tracks the resolved dynamics of new flows.

C⋆=argCmin​ E​uˉt+1​−Mˉ(uˉt​;N(uˉt​)+C(uˉt​))​2,C≈τ

uˉ is the resolved state, Mˉ the coarse time-stepper, C the learned model of τ, and the expectation runs over filtered high-resolution trajectories. C is judged in the loop rather than on τ alone.
